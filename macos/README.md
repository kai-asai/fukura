# FukuraMac

macOS向けの定型文入力メニューバーアプリです。`~/Library/Application Support/fukura/snippets.json` を読み込み、`;mail` / `;thx` などを展開します。

## ビルドと起動

```bash
cd macos
swift build
swift run FukuraMac
```

## アプリと配布ZIPの作成

```bash
cd macos
./package-app.sh
```

`dist/fukura.app` と `dist/fukura-mac.zip` が作成されます。利用するMacではアプリを `/Applications` へコピーし、初回のみAccessibilityとInput Monitoringを許可します。

環境変数を指定しない場合はアドホック署名です。一般公開用はDeveloper ID証明書と公証用Keychain Profileを用意します。

```bash
CODESIGN_IDENTITY="Developer ID Application: Example (TEAMID)" \
NOTARY_PROFILE="fukura-notary" \
./package-app.sh
```

`NOTARY_PROFILE` 指定時はDeveloper ID署名、Hardened Runtime、公証、staple後にZIPを作成します。

## アプリの更新

更新対応の正式配布版ではメニューの「アップデートを確認…」で最新版を確認できます。
「自動更新」をオンにすると、更新の定期確認・ダウンロード・適用を有効にします。
初期状態はオフで、設定は再起動後も保持します。更新用URLと公開鍵が未設定の開発版では利用できません。
配布者向けの署名・公証・更新フィードの準備は [UPDATES.md](UPDATES.md) を参照してください。

## ログイン時に起動

`fukura.app` を `/Applications` から起動し、メニューバーのfukuraアイコン → `ログイン時に起動` をオンにします。macOSから承認を求められた場合は、`システム設定 > 一般 > ログイン項目と機能拡張` でfukuraを許可してください。`swift run` はログイン項目登録の対象外です。

旧bonが起動中の場合、fukuraはbonの終了とログイン項目の確認を案内します。bonを終了しない場合はfukuraの展開を停止し、二重置換を防ぎます。

## 辞書を編集する

メニューバーのfukuraアイコン → `辞書を編集…`（`⌘E`）で編集画面を開きます。初回起動時は自動で開きます。

- トリガー・本文の検索
- 追加、複製、削除、有効 / 無効の切り替え
- `⌘S` で検証して保存
- 未保存のまま閉じると破棄確認
- 保存前の辞書を `snippets.backup.json` へ自動バックアップ

本文は通常の複数行テキスト欄です。JSON用の `\n` を手書きする必要はありません。

## 保存先と旧名からの移行

```text
~/Library/Application Support/fukura/snippets.json
```

fukuraの辞書が未作成の場合、旧 `~/Library/Application Support/bon/` または `SnippetExpander/` の辞書とバックアップを自動コピーします。旧ファイルは削除しません。どの辞書もなければサンプルを作成します。

## 権限

1. メニューの `プライバシー設定を開く` からシステム設定を開く。
2. `プライバシーとセキュリティ > アクセシビリティ` で起動中のターミナルまたはfukuraを許可する。
3. `プライバシーとセキュリティ > 入力監視` でも同じ対象を許可する。
4. FukuraMacを終了して再起動する。

`swift run` で起動する場合、許可対象はターミナルになることがあります。`.build/debug/FukuraMac` を直接起動する場合はそのバイナリを許可します。

## トラブルシュート

メニューに辞書の状態とは別に「入力監視」の状態を表示します。
macOS 27では従来のアクセシビリティ権限は「デバイスの制御とデータアクセス」にあります。
権限を許可した後は「入力監視を再開始」で監視を作り直せます（一時停止の設定は維持します）。

展開できない場合は「入力監視を再開始」→ TextEditのABC入力で登録済みトリガーを手入力 →
「入力監視の診断情報…」を開き、表示された情報を共有してください。

- EventTapが有効でも「キー受信」が0: イベントが届いていない状態です。
- キー受信は増えるが「判定可能な文字」が増えない: 修飾キー、文字取得、制御文字などの判定で除外されています。
- 判定可能な文字は増えるが「トリガー一致」が0: 入力と有効な辞書トリガーの一致を確認してください。
- トリガー一致は増えるが展開されない: 一致後の安全確認・イベント送信・貼り付けを調べます。一致件数は貼り付け成功を意味しません。
- SecureInputがtrue: セキュア入力による待機です。パスワード入力を終えてください。アプリはこの保護を解除しません。

件数は起動・監視再開始からの累計です。入力文字、キーコード、定型文、クリップボード内容、
入力先のアプリ名は診断に含めません。診断画面の内容と監視状態の変化は
OSLogの `com.kaiasai.fukura.mac / InputMonitoring` に公開情報として出力します。

タイムアウト通知では権限を確認して監視を再度有効にし、途中のトリガーと予約済みの展開を破棄します。
ユーザー入力による無効化通知では自動復帰せず、手動再開始を待ちます。
これは監視の堅牢化と診断のための変更で、macOS 27で報告された症状の解消を保証するものではありません。

### 変更後の実機確認

1. `swift build` と `./package-app.sh` を実行し、アプリから起動する。
2. TextEditで展開し、キー受信・判定可能な文字・一致が増えることを確認する。
3. 一時停止中に入力し、展開されないこと、監視再開始後も一時停止が維持されることを確認する。
4. 監視再開始を繰り返し、1つのトリガーが1回だけ展開されることを確認する。
5. 権限を取り消すと監視状態に反映され、再許可・監視再開始で復帰することを確認する。
6. パスワード欄などでセキュア入力を有効にし、待機表示になることと通常入力への復帰を確認する。
7. デバッガでイベントタップのコールバックを一時停止してタイムアウトさせ、再開後に
   タイムアウト・復帰件数が増えることを確認する。途中まで入力したトリガーは引き継がれないこと。
8. 辞書の保存・再読み込みが監視状態表示を上書きしないこと、ログに入力内容がないことを確認する。

CIのmacOSビルドだけでは権限・入力監視・貼り付けの実機動作は確認できません。

- メニューバーに出ない: `swift run FukuraMac` が起動し続けているか確認する。
- トリガーが置換されない: AccessibilityとInput Monitoringの両方を許可し、再起動する。
- JSONが読み込めない: メニューのステータス、またはターミナルの `[fukura]` ログを確認する。
- 置換タイミングがずれる: まずTextEditで確認する。
